v6 Curve Fitting — Procedure

The actual mathematics behind fit_v6_curves.py: the filter operators, the edge-detection scoring function, the plateau estimator, and the formulas that derive every seed time and every adaptive parameter from the signal itself.

1Signal model and notation

The raw capture is a sequence of position samples:

y[n],  n = 0 .. N-1,   sampled at  dt = 1/1000 s   // 1 kHz
t[n] = n · dt

Everything below is either a filter applied to (a slice of) y, an index derived from y by thresholding or scoring, or a parameter computed from the commanded MRES/rate rather than from y at all. Nothing is fit in the least-squares sense — every "fit" here is a deterministic filter or estimator applied to the measured signal, composed in a fixed order per block.

2Core filtering operators

Two operators, and one composition of them, are reused throughout everything that follows.

M2.1 Median despike, Mw

Window duration w (ms) → odd sample count:

k  = round(w · 1e-3 / dt)
k' = k + (1 - k mod 2)          // smallest odd integer >= k
r  = (k' - 1) / 2

M_w[y](n) = median( y[n-r], y[n-r+1], ..., y[n+r] )

edge-replicated ("nearest") outside [0, N-1]. Suppresses single-sample glitches without attenuating a real transition that spans several samples.

G2.2 Centered Gaussian smoother, Gσ

σ_n = σ · 1e-3 / dt
R   = max(1, ceil(4 · σ_n))
g[k] = exp(-k² / (2σ_n²)) / Σj=-R..R exp(-j² / (2σ_n²)),   k = -R .. R

G_σ[y](n) = Σk=-R..R  y[n-k] · g[k]

g is symmetric → zero-phase: no time lag is introduced, unlike a causal (one-sided) smoother.

S2.3 Combined smoothing pass, Sw,σ

S_{w,σ}[y] = G_σ( M_w[y] )          // despike, then smooth

Every fit in this pipeline that isn't a piecewise-constant plateau is one evaluation of Sw,σ for some (w, σ) — the entire design space is which (w, σ) to use, and that choice is exactly where "reference" and "dynamic" (§4, §5) diverge.

3Seeding: recovering transition times with no event log

v3's equivalent pipeline seeds each expected step transition from a logged MOVE_ACK timestamp. EXPrun.csv has no such log, so 30 seed times τ₀ .. τ₂₉ (15 forward-edges, 15 return-edges) are recovered from y itself before any fitting happens.

3.1Jump-event detector

d[n] = | y[n+1] - y[n] |
E = { n : d[n] > θ },   θ = 0.8 µm/sample

Consecutive members of E join the same event iff t[ni+1] - t[ni] < 0.15 s. Each event j has a start time t_j and duration Δ_j (last − first, within the group). A marker (fast, large out-and-back move) produces one long event (Δ_j from ~80 ms to ~1.5 s, scaling with its own amplitude); a single oscillation microstep produces one short event (Δ_j < 80 ms).

3.2Case A — direct detection (MRES 1, 4 here)

Let M = { j : Δ_j ≤ 80 ms }. If a contiguous run of M, sorted by time, has consecutive gaps tj+1 - t_j ∈ [0.8, 1.3] s (the firmware's 1 s forward/return dwell) and length ≥ 28, take its first 30 members' start times directly:

τ_i = t[run[i]],   i = 0 .. 29

3.3Case B — derived from marker timing (MRES 16, 32 here)

At finer MRES the commanded step rarely clears θ, so §3.2 fails. Instead:

next_onset  = t_j   // marker event immediately preceding this group's
                    // first leg (25 s window ending at that leg's
                    // own ramp-threshold crossing)

(t_j, Δ_j)  = OSCILLATION marker's return-move event
              // searched further back, strictly before next_onset - 5s

osc0   = t_j + Δ_j + 0.5 s              // move finishes, then settle
period = ( next_onset - osc0 ) / 15
τ_2k   = osc0 + k · period,          k = 0 .. 14   // forward
τ_2k+1 = osc0 + (k + 0.5) · period,  k = 0 .. 14   // return

t_j + Δ_j — the move finishing, not starting — matters: using t_j alone put osc0 mid-ramp on the marker's own return move in one checked case (MRES 16). The derived period agrees with the directly-detected periods from §3.2 to within 0.3% only once Δ_j is included.

4The reference fit: piecewise-constant plateaus

Applied to the oscillation block, given seeds τ₀..τ₂₉ from §3 and search half-width h = 0.35 s.

4.1Edge refinement

ŷ = M_9ms[y]                          // despike first
s = round(0.006 / dt)                 // 6 ms half-span, in samples

for each seed τ_i, search n ∈ [ idx(τ_i - h), idx(τ_i + h) ]:
  score(n) = | ŷ[n+s] - ŷ[n-s] |
  edge_i   = argmax_n  score(n)

score is a discrete central-difference slope estimate over a fixed 12 ms baseline — maximizing it finds the steepest local change (the real transition) even if the seed is off by up to h. (edge_i is bumped to edge_{i-1}+1 if it would not otherwise strictly increase.)

4.2Plateau estimate

W = edge_i+1 - edge_i                         // interval width, samples
g = min( round(0.2/dt), ⌊W/4⌋ )               // guard, samples

fitted[n] = median( ŷ[edge_i+g] .. ŷ[edge_i+1 - g] )   for all n in the interval

Trimming g samples off both sides before taking the median excludes the transition's own overshoot/ring-down from the plateau estimate by construction — a piecewise-constant, idealized-command curve. The overshoot exclusion is deliberate, not incidental.

Trajectory legs get the continuous analogue, no edges at all:

reference = S_{9ms, 20ms}[y]   // one heavy pass over the whole ramp

5The dynamic fit: transient-preserving

No edges, no plateaus — a single evaluation of Sw,σ (§2.3) over the whole block, with (w, σ) chosen light relative to whatever structure needs to survive.

5.1Oscillation blocks — fixed

Every transition is isolated in time by a 1 s dwell on each side, so one fixed pair suffices:

dynamic = S_{3ms, 2ms}[y]
Measured Reference — §4 Dynamic — §5

5.2Trajectory legs — adaptive per leg

(w, σ) scale to that specific leg's own commanded step interval, because the interval is not constant across this dataset:

Δx = FULL_STEP_UM / mres              // commanded step size, µm
v  = rate_fsps · FULL_STEP_UM         // commanded velocity, µm/s (indep. of MRES)
τ_step = 1000 · Δx / v                 // step interval, ms

w = clip( 0.25 · τ_step, 1.0, 9.0 )    // despike width, ms
σ = clip( 0.15 · τ_step, 0.5, 5.0 )    // Gaussian sigma, ms

dynamic = S_{w, σ}[y]

τ_step spans three orders of magnitude across this dataset — 36 ms (MRES 1, 27.5 full-steps/s) down to 0.156 ms (MRES 32, 200 full-steps/s), the latter already below the 1 ms sample period — which is why (w, σ) is recomputed per leg. At the floor (w=1.0, σ=0.5) the filter does essentially nothing beyond despiking, and correctly renders a smooth line rather than a fabricated staircase: there is no recoverable step structure once τ_step < dt.

Every leg's resolved (w, σ) is written to fit_summary.json under trajectory_legs.dynamic.params_by_leg_ms.

6Zoom-window sizing (visualization, not a fit)

The two trajectory zoom plots (apex, mid-ramp) are windowed to a target number of commanded steps rather than a fixed duration, using the same Δx, v as §5.2:

half_window = max( κ · Δx / v,  n_min · dt ),   κ = 10,  n_min = 40

The n_min · dt floor exists so a fast-rate + fine-MRES leg (steps under 1 ms apart) still gets a window with a visible number of raw samples in it. A fixed-duration window (tried first) is why an earlier version of this plot was indistinguishable at fine MRES: the same 1 s window that shows ~4 steps at MRES 1 packs in ~128 at MRES 32.

8Known limits

  • Sub-sample-period steps aren't recoverable (§5.2): at MRES 32 fast, τ_step < dt, so there is no staircase in the raw signal for any filter to preserve.
  • Case B (§3.3) depends on marker timing being well-formed — cross-checked against Case A to 0.3% agreement, but only 4 MRES groups' worth of validation exists in this dataset.
  • Both fits assume the extraction window itself is correct (ramp_extent for legs, the seed-time span for the oscillation) — that boundary detection lives in ids_common.py / plot_v6_exp_run.py, documented in ../../analysis/README.md, not in this script.
